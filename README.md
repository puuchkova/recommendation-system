# Выбор товара с учётом потребностей и бюджета
Учебный проект по теме 1 дисциплины «Рекомендательные системы и системы поддержки принятия решений».

## Быстрый запуск
Python 3.10–3.11. В терминале перейдите в эту папку:
```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m src.evaluation
python -m streamlit run app.py
```
Windows: вместо `source` выполните `.venv\Scripts\activate`.
Проверки: `python -m pip install pytest`, затем `python -m pytest -q`.

## Что реализовано
* K-means по поведенческим признакам, стандартизация, silhouette.
* Контентная фильтрация: TF-IDF категорий, брендов, описаний + числовые характеристики.
* Item-based коллаборативная фильтрация на матрице оценок.
* Взвешенная гибридизация; холодный старт через сглаженные оценки популярности.
* Взвешенная аддитивная полезность (utility) и признак Парето-оптимальности для каждой альтернативы.
* TOPSIS как дополнительный метод СППР: цена — минимизируемый критерий; рейтинг и учебная производительность — максимизируемые.
* Жёсткие ограничения бюджета и категории; исключение известных товаров.
* Streamlit: рекомендации, объяснения баллов, экспорт, интерактивные графики сегментов и каталога.
* Сравнение с популярностью, Precision/Recall/NDCG@10, покрытие.
* Отдельная нейронная модель на TensorFlow Recommenders, подключаемая в интерфейсе.

## TensorFlow Recommenders
В совместимом Python 3.10/3.11 окружении:
```bash
python -m pip install -r requirements-tfrs.txt
python -m pip install --no-deps tensorflow-recommenders==0.7.7
python -m src.tfrs_model
python -m streamlit run app.py
```
В боковой панели выберите TensorFlow Recommenders. Модель обучается на train, сохраняет баллы и test RMSE. В основной таблице evaluation.csv сравниваются методы с item-based CF; метрики TFRS находятся отдельно в reports/tfrs_metrics.json. Установленные версии TF/Keras намеренно совместимы; до импорта TF включается TF_USE_LEGACY_KERAS=1.

## Данные и честность результатов
В data сохранены исходные учебные данные пользователя: 500 товаров, 1000 пользователей, синтетические оценки. Цены не актуальны, товары не являются реальными предложениями. Текстов реальных отзывов в исходниках нет. Нельзя представлять этот набор как результат парсинга. Возраст и заданные генератором предпочтения не используются для кластеризации: она основана на наблюдаемых взаимодействиях.

Для реального сбора выбрана альтернатива Wildberries из задания (одновременно подключать Ozon не требуется). API продавца даёт данные его каталога, а не весь маркетплейс. Нужны разрешения на контент, цены и отзывы. Задайте WB_API_TOKEN в локальном окружении, затем:
```bash
python -m src.collect_wb --out data/raw_wb --max-pages 10
python -m src.normalize_wb --raw data/raw_wb --out data/real_wb
```
Токен не включён в проект. Не публикуйте сырые ответы API. manifest.json отмечает ограничение числа страниц и неполноту; архивные отзывы не загружаются. На 429 соблюдается Retry-After с повтором; для базовых тарифных токенов может потребоваться большой интервал, сверяйте актуальные лимиты. Нормализатор сохраняет характеристики и тексты отзывов, агрегирует оценки только по собранной выборке; это не глобальный рейтинг WB. Для разных размеров берётся минимальная цена, только RUB. Производительность из API не выдумывается.

Отзывы сами по себе не дают идентификатор пользователя с полной историей покупок. Для персональной CF нужны отдельные обезличенные users.csv и interactions.csv с реальными согласованными ID. Не соединяйте реальные товары и синтетическую историю по случайно совпавшим ID. Для переключения набора в app.py замените load_data() на load_data(ROOT/'data/real_wb') после подготовки всех трёх таблиц. Для реального каталога используйте TOPSIS с нулевым весом cpu_score до появления проверенных характеристик. Модель TFRS после смены данных нужно переобучить.

## Схема CSV
products: product_id, category, brand, price, ram, storage, screen_size, cpu_score, rating, reviews_count; необязательно name, description. users: user_id, budget (прочие исходные поля допускаются). interactions: user_id, product_id, rating (1–5), timestamp. ID уникальны в каталогах, пары пользователь–товар в истории должны быть агрегированы. Время — единый формат и часовой пояс.

## Структура
app.py — интерфейс; src/ — модели, кластеризация, сбор и оценка; tests/ — проверки; data/ — учебные данные; reports/ — отчёт и измеренные результаты.

## Ограничения
TOPSIS зависит от набора сравниваемых альтернатив. Веса 0,5 и 0,8/0,2 — явно заданные учебные параметры, не оптимальные значения. Сходство характеристик разных категорий ограниченно интерпретируемо: используйте фильтр категории. Гибрид не обязан превосходить популярность; вывод делается по измеренным метрикам. Матрицы сходства плотные: решение рассчитано на учебный каталог, для крупного нужны sparse/ANN. K-means описывает сегменты и не используется как скрытая добавка к итоговому баллу.

## Источники
Требования: предоставленный РПД, тема 1 и общие критерии оценки проектов (включая ≥3 методов СППР).
* https://dev.wildberries.ru/ — документация API российского кабинета.
* https://dev.wildberries.cn/docs/openapi/item-management — официальные схемы управления каталогом.
* https://dev.wildberries.cn/docs/openapi/customer-communication — официальные схемы отзывов.
* https://www.tensorflow.org/recommenders — TensorFlow Recommenders.
* https://github.com/tensorflow/recommenders — исходный код и требования совместимости.

Три классических метода СППР: TOPSIS, взвешенная аддитивная свёртка (utility), анализ Парето. Парето показывает недоминируемые варианты, а не подменяет ранжирование. K-means и рекомендательные алгоритмы дополняют эти методы.

TFRS устанавливается отдельной командой --no-deps после установки зависимостей: его метаданные на macOS требуют устаревший tensorflow-macos, что конфликтует с единым пакетом tensorflow на Intel Mac.
