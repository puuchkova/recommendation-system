# Система рекомендаций товаров

**Выполнили: Пучкова Анастасия и Смолина Надежда.**

Проект по теме «Выбор продукта (товара)» дисциплины «Рекомендательные системы и системы поддержки принятия решений».

## Описание проекта

Веб-приложение помогает выбрать товар с учётом бюджета, категории и истории оценок. Пользователь задаёт параметры, получает ранжированный список товаров, сравнивает результаты разных методов и скачивает рекомендации в CSV.

## Выполненная работа

- Подготовлены и проверены таблицы товаров, пользователей и взаимодействий.
- Реализована сегментация пользователей методом K-means по покупательскому поведению, представленному историей оценок.
- Разработана контентная модель на основе TF-IDF и числовых характеристик товаров.
- Реализована коллаборативная фильтрация Item-based CF.
- Создана гибридная модель с настраиваемым весом контентной и коллаборативной частей.
- Добавлены методы TOPSIS, взвешенной аддитивной свёртки и анализа Парето.
- Разработан дашборд Streamlit с фильтрами, графиками, объяснением баллов и экспортом результатов.
- Проведена оценка качества по Precision@10, Recall@10, NDCG@10 и покрытию каталога.
- Подготовлены адаптер Wildberries API, отдельный модуль TensorFlow Recommenders, отчёт и презентация.

## Данные

Демонстрационный набор содержит 500 товаров, 1 000 пользователей и 12 619 оценок. Категории: ноутбуки, смартфоны, планшеты, наушники и умные часы.

Данные синтетические. Цены, рейтинги и характеристики используются для учебного эксперимента и не являются актуальными предложениями магазинов. Реальные отзывы и данные Wildberries API в текущий набор не входят.

## Методы

Контентная модель объединяет косинусное сходство текстовых признаков и числовых характеристик. Коллаборативная модель использует сходство товаров по оценкам пользователей.

Гибридный балл: `H = α × Content + (1 − α) × CF`. По умолчанию `α = 0,5`.

В режиме `hybrid+topsis` итоговый балл равен `0,8 × H + 0,2 × TOPSIS`. Для TOPSIS и аддитивной свёртки используются цена, рейтинг и условная оценка производительности `cpu_score`. Анализ Парето отмечает недоминируемые альтернативы. Пользователь может менять веса критериев.

Товары дороже бюджета и ранее оценённые товары исключаются из выдачи. Для нового пользователя система использует сглаженные средние оценки и заданные потребности.

## Запуск

Требуется Python 3.10–3.11. Команды выполняются из папки проекта.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

В Windows окружение активируется командой `.venv\Scripts\activate`.

Расчёт метрик:

```bash
python -m src.evaluation
```

Проверка проекта:

```bash
python -m pip install pytest
python -m pytest -q
```

## Результаты

Основной режим прошёл 6 автоматических тестов. Последние два события каждого пользователя выделены в тестовую выборку. Для расчёта метрик использованы 207 пользователей с тестовыми оценками не ниже 4.

В этом эксперименте модель популярности получила NDCG@10 = 0,0594, гибрид с TOPSIS — 0,0221. Покрытие каталога составило 2,4% и 71,4% соответственно. Полные результаты приведены в `reports/evaluation.csv`.

Silhouette для K-means с четырьмя кластерами равен 0,1543, что указывает на слабое разделение сегментов на текущем наборе.

## Дополнительные модули и ограничения

`src/collect_wb.py` и `src/normalize_wb.py` предназначены для сбора и подготовки данных разрешённого каталога продавца Wildberries. Для запуска нужен токен `WB_API_TOKEN` с соответствующими правами. Фактический сбор не проводился из-за отсутствия доступа к API.

`src/tfrs_model.py` содержит отдельную модель TensorFlow Recommenders. Обучение этой модели не проверено. Основной запуск использует Item-based CF и не требует TensorFlow.

Для применения на реальных данных необходимы актуальный каталог, проверенные характеристики и отдельная обезличенная история взаимодействий. Результаты синтетического эксперимента не подтверждают качество рекомендаций для реальных покупателей.

## Структура проекта

- `app.py` — веб-дашборд.
- `src/` — модели, кластеризация, подготовка данных и оценка.
- `data/` — демонстрационные данные.
- `tests/` — автоматические проверки.
- `reports/` — отчёт, презентация и результаты расчётов.
- `requirements.txt` — зависимости основного приложения.
- `requirements-tfrs.txt` — дополнительные зависимости для модуля TFRS.
